# Архитектура

Это высокоуровневая карта того, как устроен VD Infos. Она описывает форму
приложения, а не каталог того, что он читает: смысл отладчика методов - положить каждое
показание перед вами, а читать их вам самим на собственном устройстве.

## Цели проектирования

- **Одно значение, каждый метод.** Для каждого фрагмента информации читать его через каждый
  метод, способный его прочитать, и выстраивать показания в ряд. Отладчик выносит улики на поверхность; он
  не выносит суждений.
- **На устройстве и тихо.** Без сети, без аккаунта, без фоновой работы. Приложение работает
  только пока оно открыто.
- **Читаемо машинами.** Весь результат - это один машиночитаемый документ, так что
  инструмент получает ту же картину, что и человек. Смотрите [ИИ-агенты](AI-AGENTS.md).
- **Маленькое там, где это важно.** Нативный компонент намеренно держится крошечным и простым.

## Линзы

*Линза* - это один способ прочитать значение. Одно и то же значение читается через несколько, чтобы
их можно было сравнить:

| Линза | Что это |
|---|---|
| **Java / SDK** | API платформы, который вызывает обычное приложение. |
| **Native / JNI** | То же значение, прочитанное из нативного кода. |
| **Shell via JVM** | Команда оболочки, порождённая JVM. |
| **Shell via JNI** | Та же команда, порождённая из нативного кода. |
| **TEE / Attestation** | Аппаратно обеспеченная аттестация ключа, где она применима. |

Выстраивание линз в ряд - это вся идея: приложение показывает, где чтения совпадают,
а где различаются. Что означает различие для данного значения, на данном устройстве,
вам читать самим.

## Как проходит сканирование

```
core/model      immutable domain: Lens, Category, Verdict, ProbeSpec, ProbeResult
probe/          the probes and the bridges they use (JNI, reflection, data lists)
engine/         ProbeEngine: parallel fan-out, streams results as they land
data/           SnapshotStore (persist the report), Exporter (share as JSON / text)
ui/             Jetpack Compose, Material 3, dynamic colour, live progress
cpp/            native_probes.cpp: the native lens, dependency-free
```

- **Параллелизм.** Зонды расходятся по диспетчеру с ограниченным числом разрешений;
  результаты поступают в интерфейс по мере завершения, с живым индикатором прогресса.
- **Ничего в фоне.** Без служб и без запланированных сканирований. Приложение читает только
  пока открыто и закрывает себя, когда его оставляют без дела.
- **Нативный слой.** Один небольшой `.so` без зависимостей, привязанный по имени через `RegisterNatives`,
  намеренно держимый крошечным и простым.

## Отчёт

Каждое сканирование производит `Snapshot`: время, когда оно было сделано, версию приложения и список
результатов, по одному на зонд, каждый с показаниями от каждой линзы и вердиктом о том, как
они соотносятся. Приложение сохраняет это в приватное хранилище после каждого сканирования и может экспортировать
те же данные. Структура задокументирована как [формат экспорта](EXPORT-FORMAT.md).

## Расширение

Большая часть того, что приложение ищет, живёт как **списки обычного текста** под
`assets/data/`, а не как код. Добавить или удалить цель - это отредактировать одну строку. Смотрите
[Участие](CONTRIBUTING.md).

## Чего VD Infos никогда не делает

- Он никогда не меняет ничего в вашей системе. Он только читает и сравнивает.
- Он никогда не общается с сетью. Он полностью работает офлайн.
- Он никогда не работает в фоне, не планирует сканирование и не держит службу живой.
- Он никогда не отправляет показание куда-либо. Отчёт покидает устройство только когда вы отправляете или
  сохраняете его, с замаскированными значениями, несущими идентичность.
