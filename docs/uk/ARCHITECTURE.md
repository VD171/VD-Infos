# Архітектура

Це високорівнева мапа того, як зібрано VD Infos. Вона описує форму застосунку, а не каталог того,
що він зчитує: сенс налагоджувача методів у тому, щоб покласти перед вами кожне зчитування, а
читати їх вам на власному пристрої.

## Цілі дизайну

- **Одне значення, кожен метод.** Для кожної одиниці інформації зчитуйте її через кожен метод,
  що може її зчитати, і вишиковуйте зчитування. Налагоджувач виносить докази на поверхню; він не
  виносить присуду.
- **На пристрої й тихо.** Жодної мережі, жодного облікового запису, жодної фонової роботи.
  Застосунок працює лише доки він відкритий.
- **Читаний машинами.** Увесь результат - це один машиночитаний документ, тож інструмент отримує
  ту саму картину, що й людина. Див. [ШІ-агенти](AI-AGENTS.md).
- **Малий там, де це важливо.** Частину, яку має бути важко обдурити, навмисно тримають
  крихітною.

## Лінзи

*Лінза* - це один спосіб зчитати значення. Те саме значення зчитується через кілька, щоб їх можна
було порівняти:

| Лінза | Що це |
|---|---|
| **Java / SDK** | Платформний API, який викликає звичайний застосунок. |
| **Native / JNI** | Те саме значення, зчитане з нативного коду. |
| **Shell via JVM** | Команда оболонки, породжена JVM. |
| **Shell via JNI** | Та сама команда, породжена з нативного коду, інша точка огляду. |
| **TEE / Attestation** | Апаратно підкріплена атестація ключів, де вона застосовна. |

Вишиковування лінз - це вся ідея: коли вони не збігаються, щось між застосунком і значенням
відповідає по-різному різним викликачам. Що це означає для певного значення на певному пристрої -
читати вам.

## Як проходить сканування

```
core/model      immutable domain: Lens, Category, Verdict, ProbeSpec, ProbeResult
probe/          the probes and the bridges they use (JNI, reflection, data lists)
engine/         ProbeEngine: parallel fan-out, streams results as they land
data/           SnapshotStore (persist the report), Exporter (share as JSON / text)
ui/             Jetpack Compose, Material 3, dynamic colour, live progress
cpp/            native_probes.cpp: the native lens, dependency-free
```

- **Паралелізм.** Проби розгортаються по диспетчеру з обмеженою кількістю дозволів; результати
  надходять потоком до UI у міру завершення, з живим індикатором прогресу.
- **Нічого у фоні.** Жодних служб і жодних запланованих сканувань. Застосунок зчитує лише доки
  відкритий і закриває себе, коли його лишають без діла.
- **Нативний шар.** Один маленький `.so`, прив'язаний за іменем через `RegisterNatives`, навмисно
  тримається крихітним, бо це частина, яку має бути важко обдурити.

## Звіт

Кожне сканування створює `Snapshot`: час, коли його зроблено, версію застосунку та список
результатів, по одному на пробу, кожен зі зчитуваннями від кожної лінзи та присудом того, як вони
співвідносяться. Застосунок зберігає це у приватне сховище після кожного сканування й може
експортувати ті самі дані. Структура задокументована як [формат експорту](EXPORT-FORMAT.md).

## Розширення його

Більшість того, що шукає застосунок, живе як **списки звичайного тексту** під
`assets/data/`, а не як код. Додавання чи видалення цілі - це редагування одного рядка. Див.
[Внесок](CONTRIBUTING.md).

## Чого VD Infos ніколи не робить

- Він ніколи нічого не змінює у вашій системі. Він лише зчитує й порівнює.
- Він ніколи не спілкується з мережею. Він повністю працює офлайн.
- Він ніколи не працює у фоні, не планує сканування й не тримає службу живою.
- Він ніколи не надсилає зчитування кудись. Звіт покидає пристрій лише тоді, коли ви поширюєте чи
  зберігаєте його, зі замаскованими значеннями, що несуть особу.
