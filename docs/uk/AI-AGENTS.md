# VD Infos для ШІ-агентів

VD Infos **створений, щоб його читали машини, а не лише люди**. Налагоджувач методів пристрою
видає багато структурованих доказів - кожне значення, зчитане через кожен метод, вишикуване для
порівняння - і ці докази набагато корисніші агенту як дані, а не як знімок екрана. Тож увесь
результат доступний як один машиночитаний документ, і застосунок від самої основи побудований
навколо цього.

Якщо ви ШІ-асистент для кодування, інструмент на основі LLM, аналітичний скрипт чи будь-яка
автоматизація, що дістається пристрою через оболонку, ця сторінка для вас.

## Чому він дружній до агентів

- **Один документ, а не екран.** Усе сканування - кожна проба, кожна лінза, кожен присуд - це
  єдиний об'єкт JSON. Жодного OCR, жодного зчитування екрана, жодного перегортання згорнутих карток.
- **Ті самі дані, що й в UI.** Файл - це не резюме. Це рівно те, що застосунок тримає всередині:
  екран показує перше зчитування згорнутого елемента, файл має їх усі.
- **Детермінована форма.** Структура стабільна й задокументована (див.
  [EXPORT-FORMAT](EXPORT-FORMAT.md)), тож одного разу написаний парсер продовжує працювати.
- **Жодної мережі, жодного облікового запису, жодного стану, яким треба керувати.** Застосунок
  зчитує на пристрої й записує файл. Ваш агент читає файл. Ось і весь контракт.
- **Офлайн за задумом.** Йому не потрібен інтернет, тож він працює так само всередині
  замкненого чи ізольованого від мережі середовища, в якому може діяти агент.

## Зчитування однією командою

Кожне сканування записує свій повний звіт у приватне сховище застосунку. Після того, як
сканування відбулося, агент читає повний результат однією командою:

```sh
su -c cat /data/data/ru.vd171.vdinfos/files/last_snapshot.json
```

- **Що він містить:** кожну пробу з її присудом і значенням від кожної лінзи, у тому ж JSON, що
  й кнопка експорту.
- **Коли він оновлюється:** наприкінці кожного сканування. Спершу запустіть сканування; файл
  завжди тримає найновіше.
- **Вимога:** root, бо файл живе у приватному сховищі застосунку. Без root замість цього
  скористайтеся вбудованою дією **поширити / зберегти як JSON** і прочитайте файл, який агенту
  передано.

## Типовий потік агента

1. Переконайтеся, що застосунок встановлено (APK **SDK_35** зі
   [Releases](https://github.com/VD171/VD-Infos/releases)).
2. Запустіть сканування - людина торкається "сканувати", або автоматизація запускає екран
   сканування застосунку - і зачекайте, доки воно завершиться.
3. Прочитайте `files/last_snapshot.json` командою вище.
4. Розберіть його за [форматом експорту](EXPORT-FORMAT.md) як вашою схемою: ітеруйте проби,
   читайте `verdict` кожної та вишикуйте полінзові `values`.
5. Дійте на структурованому результаті у власному робочому процесі.

Агент вирішує, що означають зчитування для поточного завдання; VD Infos постачає докази, чисто
й повно.

## Що агент отримує, а що ні

- Звіт несе **кожне зчитування й кожен присуд**, тож агент має повну картину, яку побудував
  застосунок.
- Значення, що несуть особу (серійні номери, IMEI, MAC-адреси, рекламні ідентифікатори тощо),
  **замасковані у поширеному/експортованому звіті**, тож звіт, який передають з рук у руки,
  лишається вільним від особистих ідентифікаторів, зберігаючи свої присуди та структуру.
  `last_snapshot.json` **на пристрої**, читаний лише застосунком або root, зберігає справжні
  значення для локального агента, якому вони потрібні.

## Документація, написана, щоб її розбирали

Ця вікі структурована для машинного читання не менше, ніж для людей: короткі розділи, стабільні
заголовки, явні імена полів і присвячена сторінка [формату експорту](EXPORT-FORMAT.md), яку
агент може сприймати як схему. Якщо ви будуєте інструмент поверх VD Infos, починайте звідти.
